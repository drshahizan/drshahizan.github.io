Prototype and Test

Build to think. Test to learn. Repeat.

12Prototype · Test
Design

Make it tangible, then let users react

A prototype is anything a user can interact with—a sketch, a paper screen, a role-play or a clickable mock-up. Prototypes should be quick and cheap so that you can learn and change direction.

Prototyping tips

  • Start building—paper, markers and sticky notes are enough to begin.
  • Build with the user in mind—decide what question this prototype should answer.
  • Label your POV—show which need the prototype addresses.
  • Keep it rough—the less time invested, the easier it is to change.

Testing tips

  • Let users experience the prototype; do not explain it first.
  • Observe what they do and ask open-ended questions about why.
  • Prototype as if you are right, but test as if you are wrong.
  • Use what you learn to refine the prototype—or to redefine the problem.

Use your Topic 02 skills: Figma and Google Stitch are ideal for quick digital prototypes, and GitHub Pages can host a clickable demo for testing.
