Data from Source Systems

People are not the only source of information. Most data today is generated automatically by systems.

The Generation stage of the lifecycle

Steps 01–07 gathered information from people and documents. A data engineer must also understand the systems that generate data continuously—the first stage of the data engineering lifecycle from Topic 03.

SourceWhat it isCampus example
FilesA sequence of bytes on disk; still a universal way to exchange data. Common formats: Excel, CSV, TXT, JSON and XMLA department emails a CSV of parking permits each month
APIsA standard way for systems to exchange data over a networkA mobile app requests available parking bays from a server
Application databases (OLTP)Databases that store an application’s current state and handle many small reads and writesThe permit-renewal system records each renewal
LogsRecords of events that occur in a system, usually with a timestampGate barriers log every entry and exit
Messages and streamsEvents sent between systems as they happen; a stream keeps an ordered, replayable recordSensors report when a bay becomes free

Two ways to record change

CRUD

Update in place

Create, read, update and delete. When a student changes their car plate, the old value is overwritten.

Insert-only

Keep history

A new record with a timestamp is added instead of updating. The current value is the latest record, and the full history is kept.

Three kinds of time

Events travel through a pipeline, so record a timestamp at each step: event time (when it happened in the source), ingestion time (when it arrived) and processing time (when it was processed). The gaps between them reveal delays.
