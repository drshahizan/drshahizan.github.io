Key terms in one place

Search for a term or a word in its meaning.

TermMeaning
Data engineeringDeveloping, implementing and maintaining systems and processes that turn raw data into high-quality, consistent information for downstream use.
Data engineerA professional who manages the data engineering lifecycle, from source systems to serving data.
Data engineering lifecycleFive stages—generation, storage, ingestion, transformation and serving—that a data engineer controls.
Data lifecycleThe full lifespan of data; the data engineering lifecycle is a subset of it.
GenerationCreation of data in source systems such as applications, devices, files and logs.
StorageKeeping data so it can be retrieved; it underpins every other lifecycle stage.
IngestionMoving data from source systems into the systems where it will be stored and processed.
TransformationCleaning, combining and reshaping data so it becomes useful.
ServingDelivering prepared data for analytics, machine learning and applications.
UndercurrentA critical idea that supports every lifecycle stage.
SecurityProtecting data and systems, for example by granting only the access people need.
Data managementPractices for treating data as an asset, including governance, metadata, quality and lineage.
DataOpsAgile and DevOps practices applied to data: automation, monitoring and incident response.
Data architectureThe design of data systems to meet current needs and adapt to future ones.
OrchestrationCoordinating and scheduling many jobs so they run in order and recover from failure.
Software engineeringWriting, testing, versioning and maintaining code that runs data systems.
Upstream / downstreamUpstream work supplies inputs; downstream work consumes them. Data engineering is upstream of data science.
Data Science Hierarchy of NeedsRogati’s pyramid showing that data collection, movement and preparation must precede analytics and AI.
Data warehouseA central system designed for reporting and analysis of business data; term coined by Bill Inmon in 1989.
MPP databaseMassively parallel processing database that uses many processors to analyse large data.
Big dataVery large data sets, often described by volume, velocity and variety.
MapReduceA Google programming model for processing large data by splitting work into parallel map and reduce steps.
HadoopOpen-source framework inspired by Google’s papers for distributed storage and processing.
Public cloudRentable computing, storage and services offered over the internet on a pay-as-you-go basis.
Modern data stackA collection of off-the-shelf tools assembled to build data systems quickly.
Data lifecycle engineerReis and Housley’s term for today’s data engineer, focused on the whole lifecycle and its undercurrents.
Live data stackA predicted next stage built around streaming pipelines and real-time analytical databases.
SQLStructured Query Language; the lingua franca for querying and transforming data.
Data lakeA store that keeps large volumes of raw data in many formats, often on distributed or cloud storage (see the Uber case).
Event streamingContinuously moving data as a flow of individual events rather than in periodic batches.
Apache KafkaAn event-streaming platform created at LinkedIn; producers publish events to topics that consumers subscribe to.
Apache AirflowA workflow orchestrator created at Airbnb; pipelines are written in Python as graphs of dependent tasks.
De-identificationRemoving or masking details that could identify individuals before data is shared (see the KKM case).
Monolith / microservicesA monolith runs as one unit; microservices split a system into many small services. Neither is always better (see the Prime Video case).
Big data hubrisThe assumption that big data can replace, rather than complement, traditional data collection (see Google Flu Trends).
