Evolution of the Field

History does not repeat itself, but it rhymes. Four eras explain how today’s data engineer came to be.

02Evolution
History

Four eras of data engineering

Looking back is not a history lesson for its own sake. It helps explain why today’s tools and practices look the way they do—and why old ideas keep returning.

The four eras

1980–2000 · From data warehousing to the web

IBM engineers developed the relational database and SQL, and Oracle popularised it. Bill Inmon coined the term data warehouse in 1989; Inmon and Ralph Kimball created data-modelling approaches still used today. Massively parallel processing (MPP) databases brought the first age of scalable analytics, with roles such as BI engineer, ETL developer and data warehouse engineer. In the mid-1990s the web created companies such as Amazon and Yahoo—and far more data than vendors expected.

Early 2000s · The birth of contemporary data engineering

Traditional monolithic databases buckled under web-scale growth while commodity hardware became cheap. Google published the Google File System paper (2003) and the MapReduce paper (2004). Engineers at Yahoo built and open-sourced Apache Hadoop (2006). Amazon created elastic compute (EC2), scalable storage (S3) and NoSQL databases, then offered them as Amazon Web Services—the first popular public cloud.

2000s–2010s · Big data engineering

Open-source tools such as Hadoop, Hive, HBase, Cassandra, Spark and Presto spread worldwide. A second shift moved work from batch computing toward event streaming and “real-time” data. Big data engineers maintained large clusters of commodity hardware—until managing these complex tools became too costly, and the field began to simplify.

2020s · Engineering for the data lifecycle

Tools have become modular, managed and highly abstracted. The modern data stack assembles off-the-shelf products like LEGO bricks. Engineers now spend more time on higher-value concerns—security, data management, DataOps, architecture and orchestration—and must understand privacy regulation. Reis and Housley call this person a data lifecycle engineer.

“What’s old is new again”

Data management, data quality and governance were once considered “enterprisey” concerns of large companies. Now that many hard technical problems have been packaged into managed services, these concerns have returned to the centre of the field—but with more emphasis on decentralisation and agility.

The 3Vs of big data

Volume

How much data there is.

Velocity

How fast data is created and must be processed.

Variety

How many forms and sources the data comes from.
