LinkedIn and Apache Kafka

Batch systems could not keep up with real-time activity data, so LinkedIn built a new kind of data pipeline.

O4Kafka
Optional · Streaming

From batch to streaming

Around 2010, LinkedIn’s existing messaging systems were too slow and could not handle the volume of real-time activity data its growing platform produced.

At a glance

OrganisationLinkedIn
CreatorsJay Kreps, Neha Narkhede and Jun Rao
TimelineDevelopment began around 2010 · open-sourced in 2011 · Apache Top-Level Project in 2012
Topic 03 link02 Evolution: batch to event streaming · 08 Live data stack

Key ideas

  • Publish and subscribe: producers write events to topics; any number of consumers can read them independently.
  • Stored streams: events are kept for a period, so consumers can catch up or replay data.
  • High throughput: designed to handle billions of messages a day across many machines.
  • Foundation for live data: streaming platforms like Kafka are central to the “live data stack” described in Step 08.
