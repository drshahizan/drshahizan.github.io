The Technical Toolkit

Should a data engineer know how to code? Yes. Here are the languages that matter and why.

07Toolkit
Core skills

Data engineers are also software engineers

Managed services have replaced much low-level programming, but engineers who can write production-quality code still give their organisations an advantage.

Primary languages

LanguageMain roleWhere you meet it
SQLThe most common interface for databases and data lakesQuerying, transforming and modelling data
PythonThe bridge between data engineering and data sciencepandas, NumPy, Airflow, PySpark and many tool APIs
JVM languages (Java, Scala)Higher performance and access to lower-level featuresApache open-source projects such as Spark, Hive and Druid
bashThe Linux command line for scripting and operating-system tasksProcessing files with tools such as awk and sed; calling scripts from pipelines

Secondary languages

Depending on the organisation, data engineers may also meet languages such as R, JavaScript, Go, Rust, C/C++, C# and Julia—often because a particular tool or team uses them.

Spotlight

SQL: the lingua franca of data

During the big data era, custom MapReduce code briefly pushed SQL aside. Since then, SQL has returned through tools such as Spark SQL, BigQuery and Snowflake, and many streaming frameworks support it too. Reis and Housley argue that competent data engineers should be highly proficient in SQL—while also knowing when another tool is better.

Read the full story on the extension page The Comeback of SQL.

Keeping pace in a fast-moving field

The authors’ advice is twofold: focus on the fundamentals to understand what will not change, and watch ongoing developments to see where the field is going. When a new technology appears, ask where it helps in the lifecycle.
