Step 08 · Work locally

GitHub Desktop

Clone, edit, commit and synchronise repository files without using the command line.

GDDesktop
Desktop workflow

Connect your computer to GitHub

GitHub Desktop provides a visual interface for Git operations and securely connects your local project to its remote repository.

GitHub Desktop at a glance

GitHub Desktop provides a visual workflow for cloning repositories, reviewing changed files, creating commits, managing branches and synchronising with GitHub. The application simplifies common Git operations but does not remove the need to understand what each operation changes.

Fork, clone and branch are different

A fork creates an independent repository under another GitHub account. A clone downloads a repository to a computer. A branch creates a separate line of work inside a repository so changes can be developed and reviewed safely.

Write meaningful commits

A good commit represents one focused change and uses a concise message describing the result. Separate unrelated work so that the history remains understandable and individual changes can be reviewed or reversed.

Branch and pull request workflow

Create a branch for a focused task, commit and push the work, then open a pull request. The pull request provides a controlled place to explain the change, discuss feedback, run checks and approve the merge.

1. Install and sign in

Download and install

Visit desktop.github.com, download the correct version for your operating system and run the installer.

Open account settings

On Windows, select File → Options → Accounts. On macOS, select GitHub Desktop → Settings → Accounts.

Sign in to GitHub.com

Select Sign in next to GitHub.com. Your browser will open; sign in using the same GitHub account used for this course and authorise GitHub Desktop.

Configure Git

Confirm the name and email attached to your commits. Use an email associated with your GitHub account so that your contributions are recorded correctly.

2. Create or clone a repository

Option A: create a new local repository

Select File → New repository. Enter the repository name, description and local path, then select Create repository. Use this option when the project does not yet exist on GitHub.

Option B: clone an existing repository

Select File → Clone repository, choose scst1133-digital-tools, select a local path and click Clone. Use this option when the repository already exists on GitHub.com.

Know where the repository is stored

Remember the selected local path. GitHub Desktop manages this folder, while GitHub.com stores the remote copy online.

3. Make and save changes

Open the repository folder

Select Repository → Open in Visual Studio Code, or open the local repository folder using another text or code editor.

Add or edit project files

Create, edit, rename or delete the required files, then save every change in your editor. A suggested structure is shown below.

scst1133-digital-tools/
├── index.html
├── README.md
├── assets/
│   └── style.css
└── images/

Return to GitHub Desktop

GitHub Desktop detects saved changes automatically and lists the modified files under the Changes tab.

4. Review and commit changes

Review the Changes tab

Inspect each modified file and its highlighted lines. Deselect unrelated files so that one commit contains one focused change.

Write a clear summary

In the bottom-left panel, enter a short result-focused message such as Add navigation bar, Create portfolio homepage or Update project reflection.

Commit locally

Select Commit to main, or commit to the current branch. A commit records a snapshot in the local repository on your computer; it has not yet been uploaded to GitHub.com.

5. Publish or push to GitHub

Publish a new repository

If you created a new local repository, select Publish repository in the toolbar. Confirm the repository name, description, GitHub account and visibility, then publish it.

Push an existing repository

If the repository already exists on GitHub, select Push origin. This uploads your local commits to the remote repository.

Verify online

Select Repository → View on GitHub. Confirm that the files, latest commit message and commit history are visible on GitHub.com.

6. Continue working safely

Fetch before starting

Select Fetch origin to check whether the remote repository contains newer commits.

Pull remote changes

If updates are available, select Pull origin before editing. This reduces conflicts, especially when using another computer or collaborating with others.

Use a branch for focused work

Create a branch for a larger feature or collaborative task, commit and push the branch, then open a pull request on GitHub for review before merging.

→

Core workflow: Edit and save files in VS Code → Review changes in GitHub Desktop → Commit the snapshot locally → Push the commit to GitHub.com → Verify the result online.

GitHub Desktop and VS Code: one connected workflow

Which tool does what?

VS Code is the working editor for text, Markdown, HTML and code. GitHub Desktop shows local changes and performs create, clone, commit, branch, fetch, pull, publish and push actions. GitHub stores the shared remote copy and supports review, Issues, Projects and publishing.

✓

Good practice: Review the selected files before every commit. Do not commit passwords, API keys, private data or temporary system files.

Expected output

  • GitHub Desktop is installed, configured and authenticated.
  • A repository is created locally or cloned to a known folder.
  • Project files are edited and saved using VS Code or another editor.
  • Changes are reviewed and committed with a meaningful summary.
  • The repository is published or local commits are pushed successfully.
  • The latest files and commit history are verified on GitHub.com.
