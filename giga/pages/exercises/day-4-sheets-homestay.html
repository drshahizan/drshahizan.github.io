DAY 4 · MINI BUILD

Homestay requests,
saved to Sheets.

Build one small web app for the fictional Mersing Coastal Homestay. A guest submits a practice stay request; the app saves it to Google Sheets and displays saved requests for the manager.

Beginner-friendly · about 90 minutesGoogle Sheets + Apps ScriptPractice data only
G
What you will build ↓Follow the steps ↓Check your result ↓

THE TASK

One form.
One Sheet.

Create a request form and a manager list. The page itself is served by Apps Script, which connects it to its bound Google Sheet. This is the shortest beginner route: no separate API URL or GitHub Pages connection is needed for this mini exercise.

Use fictional records only. Do not enter a real guest’s name, contact details, identity number, address or payment information. For this classroom demo, use an alias such as “Guest A”.

Guest request form→Apps Script web app→Google Sheets→Manager request list
You needA Google account, access to Google Sheets, and an AI assistant to help draft the code.
Final outputA deployed demo URL, one saved practice request, and a list that reads the records from the Sheet.
Files to createOne Google Sheet, one Apps Script file named Code.gs, and one HTML file named Index.

NEW TO THIS?

How to use each prompt

  1. Complete the numbered task first.
  2. Click Copy prompt, paste it into your AI assistant and read its answer.
  3. Copy only the requested code into the named Apps Script file.
  4. Run the stated test and compare it with the expected output before moving on.

BUILD IN SMALL STEPS

From an empty Sheet
to a working demo.

SUCCESS CRITERIAA practice request is saved in Sheets and appears in the app’s manager list.
0110 MIN · PREPARE THE DATA

Create the request spreadsheet

Make a new Google Sheet named Mersing Homestay Requests. Rename the first tab Permohonan. In row 1, enter these column headings in order:

Request_IDSubmitted_AtGuest_AliasCheck_InCheck_OutGuest_CountPackageStatus
  1. Keep the header names exactly as shown.
  2. Leave row 2 onwards empty; the app will add a row after a request is submitted.
  3. Copy the Sheet ID from its URL and keep it available for the next step only if the AI assistant requests it. Never share a private Sheet link or credentials in a public prompt.
Expected output

A Google Sheet with a tab named Permohonan, eight headings in row 1 and no real guest data.

0210 MIN · OPEN APPS SCRIPT

Create the script attached to your Sheet

  1. In the Sheet, choose Extensions → Apps Script.
  2. Rename the Apps Script project Mersing Homestay Request App.
  3. Keep the default file named Code.gs. You will ask AI to draft its contents in Step 3.
Expected output

An Apps Script editor opened from the correct spreadsheet. Because it is attached to the Sheet, the script can work with that spreadsheet.

0320 MIN · BUILD THE SHEETS FUNCTIONS

Ask AI to create the server-side code

Use the prompt below. Ask the assistant to return Code.gs by itself, with a short explanation of where it goes. Do not paste example code into another file.

Prompt to copy · Generate Code.gsChatGPT or Gemini · Apps Script
I am a beginner. Generate the complete contents of Code.gs for a Google Apps Script project opened from (bound to) a Google Sheet. The sheet tab is named Permohonan and the exact header order is Request_ID, Submitted_At, Guest_Alias, Check_In, Check_Out, Guest_Count, Package, Status.

Create these functions:
1. doGet() serves the HTML file named Index using HtmlService.
2. setupSheet() checks that the Permohonan tab exists and creates the exact header row only if it is missing or empty.
3. addRequest(data) validates Guest_Alias, Check_In, Check_Out, Guest_Count and Package; checks that check-out is after check-in and guest count is a positive whole number; creates a unique request ID and timestamp; appends one row with status Pending; and returns a simple success message and request ID.
4. getRequests() reads the rows below the header and returns them as an array of objects with dates formatted as YYYY-MM-DD. Return the newest requests first.

Use SpreadsheetApp.getActiveSpreadsheet() and the tab name Permohonan. Do not create fake records, do not collect phone or email, do not use external APIs, and do not include credentials. Add beginner-friendly comments. Return only the complete Code.gs code, then explain how I should paste and save it.
  1. Copy the generated code and replace the default contents of Code.gs.
  2. Click Save project.
  3. Choose setupSheet in the function list and click Run. Approve the requested Google permissions.
  4. Return to the Sheet and confirm the eight headings appear in row 1.
Expected output

The Sheet is ready for requests. The script has functions named doGet, setupSheet, addRequest and getRequests.

0420 MIN · BUILD THE WEB PAGE

Create the request form and manager list

In Apps Script, click ＋ beside Files, choose HTML, name the file Index, and ask AI to generate the page.

Prompt to copy · Generate Index.htmlChatGPT or Gemini · HTML Service page
Generate the complete HTML for an Apps Script HTML Service file named Index. Make a clean, responsive beginner-friendly page titled “Mersing Homestay · Practice Request”.

Include:
- A form with Guest alias, Check-in date, Check-out date, Guest count and Package fields. Package options: Family Stay, Coastal Weekend, Local Experience. Clearly label this as a practice request, not a confirmed booking.
- A Submit practice request button and an area for a success or error message.
- A separate “Manager view · practice requests” section with a Refresh list button and a table showing Request ID, Submitted, Guest alias, Dates, Guests, Package and Status.
- On page load, call getRequests() and render the returned rows. On submit, call addRequest(formData) and refresh the list when successful. Use google.script.run with withSuccessHandler and withFailureHandler for both operations.
- Disable the submit button while saving and restore it after success or failure. Do not clear the form on failure.
- Use textContent or safe DOM methods to display Sheet values; do not insert Sheet data with untrusted innerHTML.
- No external libraries, external images, login passwords or API keys. Include simple accessible labels, readable contrast and mobile-friendly CSS.

Return only the complete HTML code for Index.html. Assume Code.gs provides doGet, addRequest(data) and getRequests(). Then briefly tell me where to paste it.
  1. Replace the content in Index.html with the generated page.
  2. Save the project.
  3. Check that the form and manager table are visible in the code preview if available.
Expected output

The app page has a practice request form and a separate manager list. The list is designed to load records using getRequests().

0510 MIN · DEPLOY THE DEMO

Deploy as a web app

  1. In Apps Script, choose Deploy → New deployment.
  2. Select type Web app.
  3. For this classroom exercise, follow your lecturer’s access setting. Use fictional records only. Do not select public access for a sheet containing real guest details.
  4. Deploy, authorize as instructed, then copy the Web app URL and open it in a new tab.
  5. If you change the code later, create a new version or update the deployment before testing again.
Expected output

A web app URL opens the “Mersing Homestay · Practice Request” page. Apps Script web apps are deployed through the Deploy menu and can be configured to run as the script owner or the accessing user; use the access setting specified by your lecturer.

0610 MIN · TEST SAVE AND READ

Submit one fictional request

  1. Enter a test alias such as Guest A, dates, two guests and one package.
  2. Submit the form and wait for the confirmation message and request ID.
  3. Check the Google Sheet: a new row should appear under the eight headings.
  4. Check the manager view: the submitted record should appear in the table.
  5. Refresh the page and confirm the request remains in the list.
Prompt to copy · Troubleshoot an errorPaste the exact error message after this prompt
I am a beginner building a Google Apps Script web app connected to the Permohonan sheet. Here is the exact error message: [paste the error]. Here is the relevant function or HTML section: [paste only the relevant code]. Explain the cause in simple steps. Give me the smallest safe change, tell me exactly which file and lines to replace, and describe the expected result. Do not rewrite unrelated parts of the project.
Expected output

One fictional request appears both as a new row in Google Sheets and in the manager table, with the same request ID and Pending status.

0710 MIN · CHECK VALIDATION AND ACCESS

Try an invalid request and review privacy

  1. Leave Guest alias blank and try to submit; the app should explain what is missing.
  2. Set check-out earlier than check-in and try again; it should be rejected.
  3. Enter zero guests; it should be rejected.
  4. Confirm that only fictional practice information was entered.
  5. Ask the lecturer to verify who can open the deployed URL before using the app with any real records.
Expected output

Invalid entries are blocked with a clear message. No real personal information or secret values are exposed in the page or code.

AFTER THE FIRST VERSION WORKS

Optional improvements

  • Filter the manager list by Pending, Approved or Cancelled.
  • Add a date-range search or a total request count.
  • Make a separate GitHub Pages landing page that links to the deployed request app.
  • For a real business, restrict the manager view and separate public request submission from staff-only records.

FINAL CHECK

Can a request
make the round trip?

Check the full path: the guest submits a practice request, the Sheet stores it, and the manager view reads it back.

Ready to present when…

  1. The app opens from its deployed URL.
  2. A valid practice request creates one new Sheet row.
  3. The app displays the generated request ID.
  4. The manager list shows the saved request from Sheets.
  5. Blank or invalid dates and guest counts are rejected.
  6. Only fictional data are used for this exercise.
