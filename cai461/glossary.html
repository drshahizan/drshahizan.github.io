Glossary

Thirty terms used in the lecture, each with a plain definition and a link to the module that explains it.

ABCEILMNOPRSTV
Achievement task
A task that succeeds if some state in a goal set G is reached during the run. Module 1
Baseline
A simple alternative, such as random, greedy or a single agent, that a new system must beat to be worth its complexity. Module 3
BehaviorSpace
NetLogo’s tool for running parameter sweeps with repetitions and exporting the results to CSV. Module 4
Bounded optimality
The property of being the best program that can actually run within a given machine’s time and memory limits. Module 1
Cohen’s kappa (κ)
Agreement between two annotators corrected for chance. MAST reports κ = 0.88 between experts and 0.77 for its LLM annotator. Module 5
Contract Net Protocol
A task-sharing protocol: a manager announces a task, contractors bid, the manager awards it. Costs about 3n + 1 messages per task. Module 2
Correlation ID
An identifier carried by every message in one conversation, so its steps can be joined into one trace. In FIPA-ACL, conversation-id. Module 3
Egalitarian social welfare
The utility of the worst-off agent, min over i of u_i(ω). A fairness measure. Module 2
Expected utility
The average utility of an agent’s runs, weighted by their probability: Σ u(r) · P(r | Ag, Env). Module 1
Individual rationality
Every agent is at least as well off taking part in a protocol as staying out. Module 2
LLM-as-a-judge
Using a language model with a rubric to score open-ended outputs. Must be checked for position, verbosity and self-enhancement bias. Module 5
Maintenance task
A task that succeeds if no state in a bad set B ever occurs during the run. Module 1
MAST
Multi-Agent System Failure Taxonomy: 14 failure modes in three categories, specification, inter-agent misalignment and task verification. Module 5
Nash equilibrium
An outcome in which no agent can gain by changing only its own strategy. A measure of stability. Module 2
ODD protocol
Overview, Design concepts, Details: the standard structure for describing agent-based models so they can be replicated. Module 4
Pareto efficiency
An outcome where no agent can be made better off without making another worse off. Module 2
pass@k
Probability that at least one of k attempts succeeds: 1 − (1 − p)^k for independent trials. Module 5
pass^k
Probability that all k trials of the same task succeed: p^k for independent trials. Measures consistency. Module 5
Performance measure
The designer’s score for the sequence of environment states an agent produces. The “P” in PEAS. Module 1
Price of anarchy
Cost of the worst equilibrium divided by the cost of the optimal outcome. 1 means selfishness costs nothing. Module 2
Rational agent
An agent that chooses the action expected to maximise its performance measure, given what it knows and has perceived. Module 1
Replication
Re-implementing a model independently and checking that it produces statistically similar results. Module 4
Run
A sequence of environment states and agent actions, written r. Module 1
Sensitivity analysis
Varying model parameters to see how much the outputs change, to find the parameters that need the most careful justification. Module 4
Social welfare (utilitarian)
The sum of all agents’ utilities for an outcome, sw(ω) = Σ u_i(ω). Module 2
Span
One step in a trace, with a name, start time, end time, parent and attributes such as agent name and tokens. Module 3
Task predicate Ψ
A function that returns true or false for each run. P(Ψ | Ag, Env) is the agent’s probability of success. Module 1
Trace
The complete record of one task across all agents, made of nested spans. Module 3
Validation
Checking that a model represents reality: “did we build the right model?” Module 4
Verification
Checking that the code matches the conceptual model: “did we build the model right?” Module 4
