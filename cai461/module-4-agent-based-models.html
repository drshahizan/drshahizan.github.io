Verification, validation and replication

An agent-based model is only useful if you can trust it. Three questions establish that trust, and they are not interchangeable.

Verification

Did we build the model right?

  • Does the code match the conceptual model?
  • Unit tests, step-by-step runs, extreme parameter values.

Validation

Did we build the right model?

  • Micro-face: do individual agents behave realistically?
  • Macro-face: do overall patterns look like reality?
  • Empirical: compare outputs with real data.

Replication

Can someone else get the same results?

  • Re-implement the model independently and compare outputs statistically.
  • The strongest test of both verification and validation.

Verification checks you can run today

CheckWhat you doWhat a bug looks like
Extreme valuesSet wolf gain from food to 0.Wolves survive for hundreds of ticks.
ConservationCount agents born and died each tick.The population changes by a different amount than births minus deaths.
Step-throughRun one tick at a time and inspect one agent.An agent moves twice or eats food that is not on its patch.
Seed repeatabilityFix the random seed and run twice.Outputs differ, so something is not controlled by the seed.

Source: Wilensky & Rand (2015), Ch. 7 “Verification, Validation, and Replication”; Wilensky & Rand (2007), JASSS 10(4):2.

Sensitivity analysis and parameter sweeps

  • Change one parameter at a time across a range and keep the others fixed (one-factor-at-a-time).
  • Run each setting many times; agent-based models are stochastic.
  • Look for parameters where small changes cause large output changes. These need the most careful justification in your report.
  • In NetLogo, BehaviorSpace automates sweeps and repetitions and exports results to CSV.

Example experiment: NetLogo Wolf Sheep Predation

Wolf gain from foodRunsMeasured output
1030% of runs where wolves survive 500 ticks
2030Mean and SD of the sheep population
3030Period of the population cycles
4030Ticks until one species goes extinct

4 settings × 30 runs = 120 simulations in one BehaviorSpace experiment. In practice you record every output for every setting; the table spreads them out to show the range of things you can measure.

Setting it up in BehaviorSpace

Open Tools → BehaviorSpace → New and fill in the fields like this:

; Vary variables as follows
["wolf-gain-from-food" 10 20 30 40]

; Repetitions
30

; Measure runs using these reporters (one per line)
count sheep
count wolves

; Stop condition
not any? wolves or not any? sheep

; Time limit
500

Run it with table output, then load the CSV into Python or a spreadsheet to compute survival rates, means and confidence intervals for each setting.

Beyond one factor at a time. OFAT misses interactions, for example when wolf gain only matters if grass regrowth is slow. When you have time, sweep two parameters together as a grid, or use a global method such as Latin hypercube sampling with variance-based (Sobol) indices.

Source: Wilensky & Rand (2015), Ch. 6 “Analyzing Agent-Based Models”; Wilensky (1997), NetLogo Wolf Sheep Predation model.

Reporting models: the ODD protocol

ODD (Overview, Design concepts, Details) is the most widely used standard for describing agent-based models. A model reported in ODD can be replicated and reviewed by someone who never saw your code. The 2020 update organises it into seven elements.

Overview

  • Purpose and patterns
  • Entities, state variables and scales
  • Process overview and scheduling

Design concepts

  • Basic principles, emergence, adaptation, objectives
  • Learning, prediction, sensing, interaction
  • Stochasticity, collectives, observation

Details

  • Initialization
  • Input data
  • Submodels

Where evaluation lives in ODD. The “Observation” design concept states exactly what is measured and when. Write it before you run the sweep, so your metrics are chosen in advance rather than picked after you see the results.

Source: Grimm et al. (2006), Ecological Modelling 198:115–126; Grimm et al. (2020), JASSS 23(2):7 “The ODD protocol for describing agent-based and other simulation models: a second update”.

Self-check quiz

Choose an answer for each question, then check. Every answer comes with a short explanation.

1. “Did we build the right model?” is the question of…

Validation compares the model with reality. Verification checks the code against the conceptual model.

2. Setting a parameter to an extreme value to see if the model breaks is a…

Extreme-value tests check that the code does what the conceptual model says.

3. A BehaviorSpace experiment has 5 settings and 30 repetitions. How many simulations run?

5 × 30 = 150 runs.

4. In ODD, where do you state what is measured?

The Observation design concept describes what data are collected and when.

5. Why is replication called the strongest test?

If someone else can build the model from your description and match your results, both the code and the specification are sound.
